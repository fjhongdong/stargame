# 星球大爆炸 · Planet Boom

网页版多人星球竞技游戏。包含完整中文大厅、房间码、实时联机、AI 练习、成长强化和手机触控。

在线试玩：https://planet-boom-stargame.onrender.com 。Render 免费服务闲置后再次访问可能需要等待唤醒。

## 启动

需要 Node.js 20 或更新版本。

要在本机外部浏览器里玩，Windows 双击 `start-game.cmd`，macOS 运行 `start-game.command`。也可在任意系统执行 `npm ci` 后运行 `npm run play`。启动程序会自动选择从 3001 开始的空闲端口，并打开本机默认浏览器。命令必须在你自己的电脑上执行；在云端执行只能启动云端服务。

```sh
npm ci
npm start
```

打开 `http://localhost:3001`。本机开两个浏览器标签页即可创建和加入同一个房间。局域网内的朋友可以打开服务器机器的局域网 IP，例如 `http://192.168.1.10:3001`，再输入房间码。

如果端口已被其他服务使用，可指定另一个端口启动，例如 `PORT=3002 npm start`（Linux / macOS）。PowerShell 使用 `$env:PORT=3002; npm start`。只需更改服务端端口，网页与 WebSocket 会自动使用相同地址。

```sh
npm test
```

测试覆盖真实 WebSocket 双人房间、准备和房主权限、同步移动、重连、引力吸收、碰撞碎裂、质量守恒、碎片抢回、分裂合并和随机强化。

## 核心玩法

- **大地图探索**：星域大小为 12000 × 8000，镜头跟随自己的星球，并通过小地图定位。地图保有 6000 个自然碎片，开局附近有可供成长的碎片，远处仍有完整探索空间。
- **掠过的流星**：地图中保有 24 颗小流星，直线匀速飞行速度为 90～150（此前的一半），不会被引力拉弯或减速。玩家附近的补充目标降为 1 颗，暖色尾迹也相应缩短，让流星更偶尔地掠过视野。流星撞到星球实体后碎裂，沿撞击法线推动星球，并震落受击核心 12% 的质量，形成 3 份等质量的自由碎片；核心至少保留 1 质量。流星自身也会碎成 3 份暖色碎片，合计质量 4。两类碎片都可被引力重新吸收，按碎片实际质量增加星球质量，不受成长倍率影响，也不增加分数或能量。撞击接触本身不会增加质量、分数或能量，也不显示加分飘字。离开地图或撞击后会补充新的流星。
- **引力吸收**：引力只在每颗星球的有效范围内牵引星屑与自由碎片，范围外没有引力加速度。质量越小，移动越快；质量越大，引力范围越广、吸力越强，移动速度越慢。多个星球争抢时，根据质量与距离决定主要吸引者。单独的受控星球和不同玩家之间不会因引力自动漂移；同一玩家的分身使用单独的有限范围引力。
- **实体碰撞与碎裂**：星球在实体边缘接触时碰撞、弹开，不会相互穿透。保护期结束后，只要单颗星球质量更大，就会撞裂较小星球；等大星球只发生实体碰撞。小星球按质量平均裂成 3～4 份，其中一份保留为原玩家控制的核心，其余成为等质量的自由碎片。大星球也同时剥落自身质量的 5%，成为自由碎片。碰撞按双方质量交换动量，碎片继承原运动速度，剥落会带来轻微反冲；接触点的闪光和碎屑随撞击速度增强。双方总质量保持不变。出生、碎裂保护及冷却期间显示保护环，保护结束后会重新判断尚未成功碎裂的接触；同次成功碎裂的持续接触不会重复碎裂。质量 12 的核心可再次均分为 3 份质量 4；最小可碎裂质量为 3，每份最低质量 1。
- **重新吸收**：自由碎片可被任何星球吸收，包括原玩家。碎片短暂散开后可争抢；原主人约 0.9 秒后可以重新吸收。碎裂与回收保持质量，不会靠重复回收凭空刷分。
- **核心与主动分裂**：玩家控制的存活核心不会被直接吞噬；可吸收的是星屑与自由碎片。主动分裂用于追击：单球质量达到 48 可以一分为二，分身向当前方向弹射，但各自质量减半、也更容易被撞碎；最多 8 个受控分身。弹射保留约 0.9 秒，随后同一玩家的分身在有限范围内互相吸引；实体接触后用约 1.2 秒逐渐吸收融合，供体连续缩小、吸收者连续长大，最终合为一颗。融合保留总质量、质心和动量；接触中的融合对按合计质量移动，避免小供体突然加速。范围外不会自动拉回。主动分身与碰撞产生的自由碎片是两种状态。
- **随机三选一**：总质量首次达到 60、100、160、240、360、520 时，随机提供三个不同属性。选择后立即生效，包含移动、成长、引力、引力波射程、能量恢复、技能消耗和冷却。多人对局不会暂停。降低质量再增长不会重复刷成长奖励。
- **追击与反击**：只有一颗存活受控核心时才能发波；多个分身需先融合为一颗，期间 E / R 不消耗能量或进入冷却，已经发出的波继续飞行。E 沿实际前进方向发射弧形引力波，R 沿正后方发射，逃跑时无需转身。静止时沿最后朝向或其反向发射。两者共用能量和冷却，基础消耗 30 能量。每道波对同一对手生效一次：沿传播方向推开实际被击中的分身，并剥落每颗受击星球 12% 的质量，生成 3 份等质量的自由碎片，核心至少保留 1 质量。碎片可重新争抢，质量越大受到的推力越小。双方会看到命中提示与短暂闪光。不同玩家的引力波前沿相撞会整道互相抵消，不比较体型、质量或强化等级；可用 E / R 拦截来波，自己的波互不抵消。抵消后不会再继续命中后方星球，交点短暂闪光并显示抵消提示。波的宽度、厚度和弧度按发射核心半径同比例缩放，包含发光边缘与实际命中厚度的总宽度不超过发射星球直径，尾迹也保持紧凑；飞行期间保持发射时的尺寸；扫过的自然小星尘归入原发射核心，沿用普通吸收的成长、分数、能量与戴森截获规则，自由碎片仍按原引力与接触规则收集。
- **波前瞬移**：自己最新发出的引力波仍在飞行、尚未命中任何对手时，按空格或手机分裂键可瞬移到当前波前；只移动原发射核心，保留核心 ID、质量和速度，其他分身照常运动。每道波只能瞬移一次，不额外消耗能量或进入冷却；成功瞬移会立即消耗该冲击波，双方画面同时清除波头和尾迹。镜头用短促的位移过渡跟进落点，星球的权威位置和碰撞仍立即切换，保持速度且不沿瞬移路径碰撞。被消耗的波不会再命中，也不能衔接戴森球；其他仍在飞行的波保持原状。落点与实体重叠时，服务器选择附近安全位置。最新那道波已命中、用过、被抵消、消失或原核心已不存在时，不会改用更早的波。只有已经发出的波可用，同一刻按 E / R 和空格不会直接创建并瞬移。
- **戴森球连招**：引力波真实命中后，0.9 秒内按空格或点击手机分裂键，可将发射该波的那颗核心变为戴森球，最多持续 2.4 秒，不受普通分裂的质量 48 门槛限制。环绕目标时，截获原本将被目标吸收的星尘和自由碎片，实际质量归入发射核心；不会凭空扣走目标质量。只有发射核心变形，其他分身继续正常移动。进入戴森球会结束此前波的瞬移机会，已发出的波仍继续正常飞行。期间不能再发 E / R 或分裂；包裹至少 0.6 秒后，重新按空格或点击出壳可请求提前还原。请求时锁定方向键或摇杆选择的回归侧，双方会看到约 0.3 秒的出口预告；提前还原不延长原持续时间、不返还冷却，等待期间也不会排队分裂。还原完成后需重新按一次空格，达到普通分裂门槛即可继续分裂。结束后核心在目标附近恢复，继承目标速度并有短暂回归保护；连招冷却 8 秒。戴森球不是实体碰撞体，不会把目标挤开；界面集中显示剩余时间和累计截获质量，不出现逐次吸收飘字。空格和手机按钮的优先级是可用戴森球 → 可用波前瞬移 → 普通分裂；前两者都不受质量 48 门槛限制。画面中央下方分别用紫色和青色提示连招，并在实际目标或波前绘制目的地标记。
- **联机胜负**：联机每局 3 分钟，按最终总质量排名，同质量比较分数。
- **无尽训练**：训练模式自动加入 AI，没有倒计时或自动结算，可一直探索、成长，也可随时返回大厅。吸收碎片时直接更新质量与排行榜，不反复显示飘字加分。

## 操作

| 操作 | 按键 |
| --- | --- |
| 移动 | 按住 WASD / 方向键推进；松手后惯性滑行并逐渐减速，反向按键制动、转向；鼠标不控制星球 |
| 连招 / 主动分裂 | 空格；命中后 0.9 秒内发动戴森球，包裹至少 0.6 秒后可再按提前出壳，实际还原后再按才分裂；未命中的最新行进波可瞬移，其余情况普通分裂；手机共用按钮 |
| 前向引力波 | E（单核心时追击） |
| 后向引力波 | R（单核心时反击，与 E 共用能量和冷却） |
| 选择随机强化 | 点击卡片或 1 / 2 / 3 |
| 全屏显示 | 右上角全屏按钮；Esc 退出浏览器全屏 |

游戏画面铺满浏览器窗口。进入时会尝试开启系统全屏，也可用右上角按钮切换；不支持系统全屏的浏览器仍可使用完整窗口。移动带有惯性：按键或摇杆提供推进，松手后继续滑行并受阻力减速，反向操作可以制动后转向。手机使用左侧摇杆推进，右侧提供操作按钮；横屏更方便。

## 联机与部署

`npm start` 同时提供静态网页与 `/ws` WebSocket 服务。快速匹配会加入开放的等待房间；好友房间通过六位码加入。在线模式需要至少两名玩家，大家准备后由房主开始。无尽训练自动加入四名 AI；AI 保持采集航点、接近时减速，并在远离威胁后再恢复采集。

生产部署到支持长连接的 Node.js 主机或容器。设置 `PORT` 即可更改端口，默认监听 `0.0.0.0:3001`。反向代理必须转发 `/ws` 的 WebSocket Upgrade；HTTPS 页面会自动使用 WSS。服务健康检查为 `/api/health`。

提供的 Dockerfile 可直接构建与运行：

```sh
docker build -t planet-boom .
docker run --rm -p 3001:3001 planet-boom
```

当前为单进程实时游戏服务器：房间在内存中，重启会清空，断线保留约 30 秒重连机会。多个实例需要房间路由或共享实时状态。线上服务位于 Render 新加坡区域，使用免费方案。

## 大地图性能

服务器用空间索引查询附近的引力碎片与碰撞对象，按玩家视野发送场景。实体运动按最长 1/120 秒的子步推进；高速撞击保留反弹，低速顶住时消除相互挤压的速度，沿接触面的运动继续保留。

客户端持续推进本地运动模型，按实际经过的时间分步计算，联机数据用于逐步校正误差。远近星球均使用同一连续预测时间显示，接近或远离自己时不会切换到另一条时间线。所有星球的受控核心都按实体边界参与预测碰撞，远处对手也不会相互穿透。分身融合的质量和半径也按这条时间线连续变化。星屑使用连续渲染时钟插值；引力波按固定发射时刻推进，不会随收包重新起算。撞击按实际接触时刻计算冲量，并继续推进碰撞后剩余的运动时间。短时长帧会完整分步补算碰撞，镜头使用同样的实际经过时间；网络状态过期暂停预测后，从新状态平稳恢复，不把停顿期间的旧时间一次性快进。所有质量、碎裂、吸收与强化结果仍由服务器计算。

画面只绘制视野内对象，并复用星球和碎片的图像缓存。游戏画布按约 207 万像素的上限绘制；持续掉帧时会逐级降低内部绘制分辨率，只有长时间流畅后才逐步恢复。界面文字、游戏视野、镜头和操作坐标不受影响。FPS 与网络往返时间可用于区分绘制卡顿和网络延迟；本机性能测试结果不能代表所有设备与公网连接的体验。

## 文件

- `server.mjs`：HTTP、WebSocket、房间与会话生命周期。
- `shared/engine.js`：服务器权威游戏模拟、碰撞、引力与强化。
- `public/`：无需构建的大厅与 Canvas 游戏界面。
- `test/`：游戏规则和真实双客户端网络测试。

所有星球、星空、碎片和音效均由程序生成，无需外部素材或第三方服务账号。
